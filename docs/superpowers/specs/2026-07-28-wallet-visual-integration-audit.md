# PanguPay Web 功能、可视化与动效审计

## 审计结论

当前界面已经形成稳定的 Ledger Plane 设计语言：品牌首页负责空间感，钱包内部保持安静、连续和精确。首页、解锁、总览、设置、创建与恢复流程不需要推翻。

尚未达到最终质量的部分集中在五个高价值界面：

1. **收款**只有地址文本和复制按钮，缺少二维码这一最直接的真实收款入口。
2. **发送**虽然已经支持普通、快速、跨链，但三种模式主要靠说明文字区分，用户难以在签名前理解真实后端路径。
3. **活动**只展示一行状态和截断 ID，入口接收、TXCer 可用、后台结算三个时间尺度没有可视化。
4. **凭证与安全**已经拥有 FastEvidence、AssignAck、LiabilityReceipt、CFAA 和 ExposureShares 的真实数据，但目前仍像技术字段列表。
5. **担保组织**入口页已有较完整的组织详情，而钱包内组织页仍使用旧式单选列表，信息和交互语义不一致。

## 设计判断

“所有信息都要可视化”不等于“所有信息都要动画化”。本轮采用以下边界：

- 金额、地址、TXID、状态根等需要阅读和复制的数据保持稳定。
- 转账模式切换、活动详情展开、凭证状态变化、二维码出现使用短暂动效解释变化。
- 总览资产、活动列表和安全数据不增加循环扫光、计数跳动或装饰性呼吸。
- 任何图形只表达后端已有事实，不引入信用评分、收益、手续费、实时价格或虚构最终性。

## 动效机会

| #   | 位置           | 当前问题                     | 目的               | 频率 | 方案                                                                                                                   |
| --- | -------------- | ---------------------------- | ------------------ | ---- | ---------------------------------------------------------------------------------------------------------------------- |
| 1   | 发送页模式选择 | 文案瞬间替换，路径关系不清楚 | 解释、状态指示     | 偶尔 | 路径节点在模式切换时以 `220ms var(--ease-standard)` 做一次 opacity/transform 过渡，连接线以 clip-path 从来源向目标揭示 |
| 2   | 活动详情       | 单行记录无法解释三个阶段     | 防止突变、状态指示 | 偶尔 | 展开区 `180ms` 淡入并上移 `4px`，时间线节点只在当前处理中显示静态强调                                                  |
| 3   | 安全凭证链     | 多个证据字段没有因果关系     | 解释               | 偶尔 | FastEvidence → AssignAck/LiabilityReceipt → CFAA 使用静态连接线，状态更新时只让改变的节点在 `180ms` 内变色             |
| 4   | 收款二维码     | 地址缺少可扫描入口           | 反馈               | 偶尔 | 地址切换后二维码 `160ms` 交叉淡化；复制按钮沿用现有 Check 状态反馈                                                     |
| 5   | 组织详情       | 两个页面交互不一致           | 空间一致性         | 偶尔 | 复用已有 dialog/sheet；桌面 `200ms` scale/opacity，移动端 `240ms` translateY                                           |

### 明确拒绝的动效

- 总资产持续计数或循环扫光：高频金融数据，运动会妨碍阅读。
- 每条活动进入时依次飞入：列表是高频页面，装饰性 stagger 会制造等待。
- 安全凭证连接线持续流动：容易暗示实时处理或持续成功，与真实状态不符。
- 每个按钮的明显位移和弹跳：高频操作，不符合安静的钱包主体。
- TXCer 责任份额自动旋转/轮播：精确责任数据应保持可比较和可复制。

## 前后端契约审计

前端 `GatewayClient` 已覆盖健康检查、组织发现与详情、re-online、散户地址注册、加入组织、地址与账户更新、TXCer 生命周期和签发证据、Assign 交易提交与状态、GQNC 认证查询等真实接口。

当前 `scripts/check-backend-contract.mjs` 只检查少数 URL 字符串是否存在，无法发现 method/path 组合漂移，也没有覆盖所有实际调用。它需要改成显式契约矩阵，并逐项对照后端注册路由。

## 质量基线

- Playwright 现有 25 项中 24 项通过；唯一失败是 UI 已从“暂不加入，独立使用”精简为“暂不加入”，测试选择器未同步。
- 现有深浅主题、桌面/移动断点和 Axe 基线总体通过。
- 全局 reduced-motion 当前将所有动画归零；本轮只对新增的大范围/循环动效显式关闭，保留不超过 120ms 的颜色和可见性反馈。

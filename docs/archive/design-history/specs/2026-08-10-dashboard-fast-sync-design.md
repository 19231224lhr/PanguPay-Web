# 钱包总览快速同步设计

## 目标

把总览“同步”从完整安全审计刷新改为两层更新：地址余额先完成并立即结束按钮等待，TXCer 证据、活动和权威信息随后在后台补齐。

## 最小设计

- 快速阶段请求地址余额、地址所属组织和轻量 TXCer lifecycle，不再单独请求 `/health`。已知组织时三项并行；首次发现组织时仅 lifecycle 需要第二轮请求。
- 快速阶段完成后立即更新余额、同步时间和离线状态。
- 详细阶段异步刷新活动、签发记录、跨组织投递与凭证验证；失败只影响相应详情，不回滚已经成功的余额。
- `GroupInfo` 与 `Certifier` 按组织 ID 在当前页面会话内复用；组织变化或页面重载后自然失效。
- IndexedDB 仍保存最终完整快照；不增加依赖、后端接口或持久化缓存格式。

## 正确性边界

- 同一时刻仍只允许一个同步任务。
- 后台详细阶段不得用旧余额覆盖快速阶段的新余额。
- 快速阶段必须使用权威 lifecycle 排除已转换为 UTXO 的 TXCer，避免短暂重复计入余额。
- 手动同步的余额动效只由余额指纹变化触发。
- 初始加载和离线恢复继续保留现有缓存语义。

## 验证

- 测试证明余额在详细接口完成前已经可见，并且同步按钮不再等待详细阶段。
- 测试证明健康检查不再单独调用。
- 测试证明相同组织的权威信息在会话内只请求一次。
- 测试证明 TXCer 转换为 UTXO 时不会发生余额双计。
- 运行 Dashboard 相关单测、类型检查和真实页面计时。

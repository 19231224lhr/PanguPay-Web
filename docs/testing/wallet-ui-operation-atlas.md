# PanguPay Web 当前真实 UI 操作图谱

## 适用范围

本图谱对应当前正式前端的 13 个路由：钱包身份、加密 keystore、组织接入、真实账户数据、原始/胶囊地址收款、普通/快速/混合/跨链发送、活动阶段、认证链和安全凭证。所有交易表单均进入 protocol-v2 构造、签名与真实后端提交。

## 首页入口

| 前置状态                    | 操作               | 目标             |
| --------------------------- | ------------------ | ---------------- |
| 本机没有 keystore           | 首页点击“进入钱包” | `/wallet/setup`  |
| 本机已有 keystore，但未解锁 | 首页点击“进入钱包” | `/wallet/unlock` |
| 本次页面会话已解锁          | 首页点击“进入钱包” | `/wallet`        |

入口使用共享元素过渡：价值折叠场从首页右侧移动到创建/解锁页左侧；移动端由 Logo 延续。减少动态效果下为约 120ms 的短交叉淡化。

## 创建钱包

1. 在“建立你的钱包”选择“创建”。
2. 输入至少 12 个 UTF-8 字节的密码并再次确认。
3. 点击“创建钱包并下载备份”。
4. 浏览器同时下载 `wallet.json` 与 `PanguPay-recovery.json`。此时钱包只保存在当前内存，尚未写入 IndexedDB。
5. 根据页面中的用途说明分别保存：`wallet.json` 是需要当前密码的加密日常备份；`PanguPay-recovery.json` 含未加密的账户私钥和全部 Address RootSeed，只用于忘记密码后的紧急恢复，必须离线保管。
6. 确认两份文件均已分别安全保存。
7. 点击“进入钱包”。只有此时才原子保存加密 envelope 并进入 `/wallet`。

预期：

- 两份备份均未完成并确认前，“进入钱包”不可点击。
- IndexedDB 保存 Argon2id + AES-256-GCM 加密 envelope，以及可从后端重新同步的公开 dashboard/账户元数据缓存；不含明文私钥或 RootSeed。
- LocalStorage 保存主题、语言、当前账户选择、交易链范围、本地活动 journal 和输入 reservation 等公开或可恢复状态；不保存明文私钥、RootSeed 或钱包密码。
- `wallet.json` 始终需要创建时的密码；独立恢复材料不进入浏览器持久化存储。

## 导入钱包

1. 在 `/wallet/setup` 选择“导入”。
2. 选择“wallet.json”方式并选择正式加密备份；页面明确显示文件已读取。
3. 输入该文件原来的密码。这里是在解密已有备份，不是在设置新密码，因此无需重复确认。
4. 点击“验证并导入”。

错误密码、密文/AAD 篡改、账户 ID 不匹配、RootSeed 无法派生记录地址时均停留在当前页并报错。

“私钥与 RootSeed”是独立的密钥恢复方式，不显示文件上传控件。它要求同时输入 32 字节账户私钥、32 字节 Address RootSeed，并设置和二次确认一个新的本地钱包密码；缺少 RootSeed 时明确拒绝恢复旧地址。

## 解锁与锁定

- 刷新页面后，内存秘密被清除，路由进入 `/wallet/unlock`。
- 输入密码并点击“解锁钱包”恢复同一账户和地址。
- 密码错误时，密码框下方只出现一条“无法解锁，请检查密码”反馈；密码被清空并重新聚焦，不暴露内部错误字符串，也不修改本地钱包。
- 忘记密码时点击“忘记密码？”进入 `/wallet/recover`：使用独立恢复材料设置新密码并重建 keystore。
- 没有恢复材料时，点击“清除本地钱包并重新开始”进入独立确认界面；恢复文件与密码表单会被隐藏。再次点击“再次点击，确认清除”后删除本设备的加密副本并重新创建或导入；该操作不会撤销链上资产。
- 点击账户头像打开账户菜单，再明确选择“锁定钱包”；点击头像本身不会锁定。
- 设置页也保留“立即锁定”操作，执行后清除内存秘密。
- 已解锁用户可在“设置与备份”重新导出独立恢复材料；导出依赖内存中的已解锁秘密，锁定状态下不可用。
- 连续 15 分钟没有指针、键盘或触摸活动时自动锁定。

解锁页与恢复页的主要状态在 1440×900、1366×768 和 1024×768 桌面视口内不需要滚动。创建流程内容较长时，只有右侧表单区域可以滚动；恢复页在极矮视口仍可滚动，但不显示破坏视觉连续性的内部滚动轨道。

## 钱包与担保组织接入

解锁后先进入 `/wallet/entry`，页面从后端恢复真实身份：

- 已加入担保组织：验证组织仍存在后直接进入总览，不重复询问。
- 已登记为独立账户：直接进入总览，之后仍可在“担保组织”页申请加入。
- 新账户：展示可用担保组织，并允许“加入所选组织”或“暂不加入”。

每个组织条目可打开详情，查看组织 ID、质押地址和金额、担保/审计节点数量、Assign/Aggregation 入口以及是否支持快速、跨链能力。打开详情不会自动选择或加入组织。

加入过程只有权威 re-online 与地址路由确认成功后才进入钱包；失败时停留在当前页并给出重试入口。页面过渡只解释状态变化，不制造额外网络等待。

## 钱包总览

页面从 Gateway 同步：

- 地址与 UTXO 可用余额；
- TXCer 生命周期与可支付余额；
- 担保组织；
- 账户活动；
- TXCer issuance detail、FastEvidence、AssignAck、LiabilityReceipt、CFAA proof 和 ExposureShares。

总览只展示用户摘要。余额光带仅在首次真实快照、手动刷新或余额真实变化时运行一次。
后端不可用时显示离线快照和缓存时间。

### 地址账本

总览的“你的收款地址”区域列出每个地址的币种、网络、UTXO/TXCer 组成、完整地址和权威登记状态。

1. 点击“新建地址”，选择币种并输入钱包密码。
2. 本地派生新地址后，客户端向当前 Assign（组织成员）或 Committee（独立账户）提交真实地址登记。
3. 只有登记成功的地址才显示为可正常使用；失败项提供明确重试。
4. 点击“归档”后先检查它是否为最后地址、是否仍有余额、reservation 或待处理交易。
5. 组织成员还必须先完成权威解绑；任一步不确定时均不修改本地地址状态。

归档只从日常选择器隐藏地址，不删除加密 keystore 中的 RootSeed，因此不是秘密销毁操作。

## 收款

1. 点击总览余额区中的“收款”。
2. 从地址选择器选择一个由当前 RootSeed 确定性恢复的地址。桌面端使用锚定在输入框下方的 `AppSelect`，移动端使用系统原生选择器；两者保存的是同一个完整地址值。
3. 页面本地生成该公开地址的二维码；切换地址时二维码同步更新。
4. 点击“复制地址”。

### 胶囊地址

1. 在收款页切换到“胶囊地址”。
2. 点击“生成胶囊地址”；组织成员由所属组织签名，独立账户由委员会签名。
3. 客户端取得权威公钥并验证返回的胶囊后，才显示二维码和复制入口。
4. 页面标明胶囊是可重复使用的签名隐私别名，原始地址仍然有效。
5. 切回“原始地址”后二维码和复制内容必须同步恢复；生成失败时原始地址收款仍可使用。

二维码和复制内容都只有公开地址或已验签胶囊，不读取或展示 RootSeed，也不调用外部二维码服务。

## 发送

发送页允许选择来源地址、快速 / 普通 / 跨链模式、收款地址与精确金额。转账模式统一使用带共享滑动镜片的 `SegmentedControl`，来源地址统一使用 `AppSelect`。页面不再展示三套协议流程图，模式能力以审核内容和真实结果状态为准。

独立账户只能选择普通模式；组织成员可以使用快速和跨链。点击“审核交易”后页面展示精确金额、UTXO/TXCer 输入、找零和完整 64-hex TXID，再由用户确认签名提交。

提交结果按交易类型分开显示：

- 普通转账：入口接收与后台完成。
- 快速转账：入口接收、担保/组织确认、收款方可用和后台结算；不等待 GQNC 才宣布 TXCer 可用。
- 跨链转账：交易已接收、担保验证、本地 GQNC 已认证、轻计算区已接收、目标链到账。只有目标链 receipt 成功并具有区块高度后才显示到账。

发送页可粘贴原始 40-hex 地址或胶囊地址。胶囊必须在选币、reservation 和签名前取得权威公钥并验签，审核页同时显示缩略胶囊和解析后的真实地址，最终 wire 只包含真实地址。跨链模式不接受胶囊地址。

余额和交易快路径不依赖 GQNC 运维接口；区块链页只读访问 Gateway 已公开的 GQNC 观测接口。

## 活动记录

活动列表优先展示方向、精确金额、状态和时间。展开一项后可查看完整 TXID 与本地已知阶段：

- 本地提交日志可以显示入口接收、TXCer 可支付和后台结算进度。
- 跨链日志在本地认证后保持“本地已认证”，轻计算区接收后显示“目标链处理中”，目标链 receipt 确认后才显示“跨链已到账”。展开后可查看 `lightTxHash`、目标区块和真实跨链耗时（后端未返回时不显示）。
- 后端只返回一条历史记录时只显示“后端记录”，不得推测缺失的阶段。
- 展开/收起使用一次 180ms 状态过渡，不对整个列表做连续或错峰动画。

## 凭证与安全

总览的安全摘要点击“查看详情”进入 `/wallet/security`：

- `Verified`：具有权威 signer 快照且完整验签成功；
- `Pending`：等待 FastEvidence、Ack、责任收据或权威上下文；
- `Failed`：完整证据存在但验证失败，TXCer 被计入隔离项；
- `Unavailable`：CFAA proof 或 Certifier 权威上下文暂不可用。

技术字段默认折叠，可展开查看 TXCerID、RecordID、RootID、LeafID 与 ExposureShare 金额。
安全页不查询 GQNC 运维状态；认证链观测仅位于独立的只读区块链页。

每条 TXCer 使用三段凭证链展示 FastEvidence、AssignAck/责任收据和 CFAA；CFAA
`Pending/Unavailable` 明确标记为后台审计，不阻塞可支付状态。多 Root 责任使用精确金额比例条展示，显示金额不经过 JavaScript 浮点数。

## 响应式导航

- 桌面端：左侧主导航包含总览、发送、活动、凭证与安全、担保组织和区块链。
- 桌面端：设置固定在侧栏左下角；账户菜单只包含账户信息和锁定钱包。
- 主题和语言统一在 `/wallet/settings` 的“外观与语言”区域调整，首页与锁定页不显示悬浮偏好按钮。
- 移动端：底部为总览、发送、活动和“我的”；总览与“我的”提供担保组织、区块链、设置和锁定入口。
- 收款由总览的等权操作按钮进入，不占用主导航。
- 所有交互目标至少为 44×44px，并支持键盘焦点和减少动态效果。

## 担保组织

`/wallet/organization` 使用与初次选择详情一致的权威信息：组织 ID、质押、当前角色、Assign、Aggregation、TXCer 审计节点、GuarNode、PeerID、API 和登记状态。

退出组织必须先点击“检查退出条件”。页面会检查可支付 TXCer、后台审计、输入 reservation 和待处理交易；全部安全后才出现“确认退出组织”。第二次点击才提交真实退出请求，并在重新同步确认不再属于组织后更新页面。

## 区块链

`/wallet/blockchain` 是只读认证链浏览器：

1. 页面读取 GQNC certified height、QCID、epoch 和委员会状态。
2. 最近认证高度按链式顺序展示；新区块到达时只触发一次轻量脉冲。
3. 点击一个高度读取对应 certified envelope，展示区块哈希、父哈希、交易 ID、系统动作和 3-of-4 QC 签名者。
4. 页面不得发起投票、治理或节点控制请求；后端离线时保留上次可验证数据并明确标记。

查询不存在的高度时显示友好空状态，不暴露 `invalid height` 等后端原始错误。区块链页的只读 GQNC 请求不参与余额、选币、签名或提交路径。

## 设置与本地资料

设置页可修改本地显示名和头像。两者只属于当前浏览器的公共展示资料，不改变账户 ID、地址、公钥或签名材料，也不进入加密秘密日志。主题、语言、备份、导出和锁定仍在同一设置页完成。

# PanguPay Web Phase 1 真实 UI 操作图谱

## 适用范围

本图谱对应 Phase 1：钱包身份、加密 keystore、真实只读账户数据、正式导航、收款和安全详情。
发送页不会签名或提交交易。

## 首页入口

| 前置状态                    | 操作               | 目标             |
| --------------------------- | ------------------ | ---------------- |
| 本机没有 keystore           | 首页点击“进入钱包” | `/wallet/setup`  |
| 本机已有 keystore，但未解锁 | 首页点击“进入钱包” | `/wallet/unlock` |
| 本次页面会话已解锁          | 首页点击“进入钱包” | `/wallet`        |

入口使用共享元素过渡：价值折叠场从首页右侧移动到创建/解锁页左侧；移动端由 Logo 延续。减少动态效果下为约 120ms 的短交叉淡化。

## 创建钱包

1. 在“建立你的钱包”选择“创建”。
2. 输入至少 12 个 UTF-8 字节的密码并再次确认。
3. 点击“创建钱包并下载两份备份”。
4. 浏览器同时下载 `wallet.json` 与 `PanguPay-recovery.json`。此时钱包只保存在当前内存，尚未写入 IndexedDB。
5. 根据页面中的用途说明分别保存：`wallet.json` 是需要当前密码的加密日常备份；`PanguPay-recovery.json` 含未加密的账户私钥和全部 Address RootSeed，只用于忘记密码后的紧急恢复，必须离线保管。
6. 确认两份文件均已分别安全保存。
7. 点击“进入钱包”。只有此时才原子保存加密 envelope 并进入 `/wallet`。

预期：

- 两份备份均未完成并确认前，“进入钱包”不可点击。
- IndexedDB 中只有 Argon2id + AES-256-GCM envelope，不含明文私钥或 RootSeed。
- LocalStorage 只包含主题和语言偏好。
- `wallet.json` 始终需要创建时的密码；独立恢复材料不进入浏览器持久化存储。

## 导入钱包

1. 在 `/wallet/setup` 选择“导入”。
2. 选择“wallet.json”方式并选择正式加密备份；页面明确显示文件已读取。
3. 输入该文件原来的密码。这里是在解密已有备份，不是在设置新密码，因此无需重复确认。
4. 点击“验证并导入”。

错误密码、密文/AAD 篡改、账户 ID 不匹配、RootSeed 无法派生记录地址时均停留在当前页并报错。

“私钥与 RootSeed”是独立的密钥恢复方式，不显示文件上传控件。它要求同时输入 32 字节账户私钥、32 字节 Address RootSeed，并设置和二次确认一个新的本地钱包密码；缺少 RootSeed 时明确拒绝恢复旧地址。

## 解锁与锁定

- 刷新页面后，内存秘密被清除，路由进入 `/wallet/unlock`。
- 输入密码并点击“解锁钱包”恢复同一账户和地址。
- 密码错误时，密码框下方只出现一条“无法解锁，请检查密码”反馈；密码被清空并重新聚焦，不暴露内部错误字符串，也不修改本地钱包。
- 忘记密码时点击“忘记密码？”进入 `/wallet/recover`：使用独立恢复材料设置新密码并重建 keystore。
- 没有恢复材料时，点击“清除本地钱包并重新开始”进入独立确认界面；恢复文件与密码表单会被隐藏。再次点击“再次点击，确认清除”后删除本设备的加密副本并重新创建或导入；该操作不会撤销链上资产。
- 点击账户头像打开账户菜单，再明确选择“锁定钱包”；点击头像本身不会锁定。
- 设置页也保留“立即锁定”操作，执行后清除内存秘密。
- 已解锁用户可在“设置与备份”重新导出独立恢复材料；导出依赖内存中的已解锁秘密，锁定状态下不可用。
- 连续 15 分钟没有指针、键盘或触摸活动时自动锁定。

解锁页与恢复页的主要状态在 1440×900、1366×768 和 1024×768 桌面视口内不需要滚动。创建流程内容较长时，只有右侧表单区域可以滚动；恢复页在极矮视口仍可滚动，但不显示破坏视觉连续性的内部滚动轨道。

## 钱包总览

页面从 Gateway 同步：

- 地址与 UTXO 可用余额；
- TXCer 生命周期与可支付余额；
- 担保组织；
- 账户活动；
- TXCer issuance detail、FastEvidence、AssignAck、LiabilityReceipt、CFAA proof 和 ExposureShares。

总览只展示用户摘要。余额光带仅在首次真实快照、手动刷新或余额真实变化时运行一次。
后端不可用时显示离线快照和缓存时间。

## 收款

1. 点击侧栏或总览中的“收款”。
2. 从地址选择器选择一个由当前 RootSeed 确定性恢复的地址。桌面端使用锚定在输入框下方的 `AppSelect`，移动端使用系统原生选择器；两者保存的是同一个完整地址值。
3. 点击“复制地址”。

页面只复制公开地址，不读取或展示 RootSeed。

## 发送

发送页允许选择来源地址、快速 / 普通 / 跨链模式、收款地址与精确金额，但按钮保持禁用。转账模式统一使用带共享滑动镜片的 `SegmentedControl`，来源地址统一使用 `AppSelect`，后续页面不得重新手写选择控件：

```text
Phase 1：不签名、不提交
Phase 2：接入 protocol-v2 交易构造、签名和提交
```

浏览器网络中不应出现 `submit-tx`、`submit-noguargroup-tx` 或 `/committee/gqnc/*`。

## 凭证与安全

总览的安全摘要点击“查看详情”进入 `/wallet/security`：

- `Verified`：具有权威 signer 快照且完整验签成功；
- `Pending`：等待 FastEvidence、Ack、责任收据或权威上下文；
- `Failed`：完整证据存在但验证失败，TXCer 被计入隔离项；
- `Unavailable`：CFAA proof 或 Certifier 权威上下文暂不可用。

技术字段默认折叠，可展开查看 TXCerID、RecordID、RootID、LeafID 与 ExposureShare 金额。
普通钱包不会直接查询 GQNC 运维状态。

## 响应式导航

- 桌面端：左侧主导航只包含总览、发送、活动和凭证与安全。
- 桌面端：设置固定在侧栏左下角；账户菜单只包含账户信息、担保组织和锁定钱包。
- 主题和语言统一在 `/wallet/settings` 的“外观与语言”区域调整，首页与锁定页不显示悬浮偏好按钮。
- 移动端：底部为总览、发送、活动和“我的”；“我的”提供担保组织、设置和锁定钱包。
- 收款由总览的等权操作按钮进入，不占用主导航。
- 所有交互目标至少为 44×44px，并支持键盘焦点和减少动态效果。
